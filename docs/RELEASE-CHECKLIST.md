# 主干道 checklist（每版必跑）

> 最后核对：2026-10-28。
>
> **主干道**= 一个真实运维用户每天都会走的那条路。这 8 项每版发版前**逐项跑一遍并留记录**
> （结果写在本文件 §2 的表格里，或在 PR 里贴同一张表）。其余功能坏了可以下版修，
> 这 8 项任意一项坏了**不能发版**。
>
> 环境覆盖见 [`TEST-MATRIX.md`](TEST-MATRIX.md)；自动化脚本见 `npm run verify`。

## 1. 八项

| # | 项 | 为什么是主干道 | 怎么跑（最短路径） | 通过标准 |
|---|---|---|---|---|
| G1 | **NLA / CredSSP 连接** | 绝大多数 Windows 主机的默认配置；NLA 挂掉等于连不上任何生产机 | 连一台开 NLA 的 Win10/Win11；再用「安全层」高级项切 `default/none/negotiate` 各连一次 | 三次都连上、状态转 `connected`；切 `none` 时若服务端拒绝，错误要能说清是认证失败而不是"超时" |
| G2 | **域账户登录** | 企业场景默认 `DOMAIN\user`，密码可能来自 Windows 凭据 | 用域账号连域内主机：① 保存密码 ② 不保存（走 Windows 凭据）③ 都不给（服务端弹框） | 三种都能进；`username:s:` 形态正确；密码不出现在日志里（`verify:log-redaction` 通过） |
| G3 | **RD 网关** | 外网/分支访问内网的唯一入口 | 配置 `gateway.hostname` + `usageMethod=always/direct/default` 各一次；观察 `.rdp` 里 `gateway*` 行 | 三种用法都能连/被正确拒绝；网关凭据提示只问一次（`promptcredentialonce`） |
| G4 | **跳板链**（经跳板连内网） | 企业最常见的网络形态：目标机不可直连 | 先连跳板机，再从跳板机上的 RDPilot 连内网机（或手动配置端口映射后直连） | 两条连接都在会话标签里、互不干扰；断开内网机不影响跳板机；探测对"不可达但可经跳板连"显示 `unknown` 而不是 `offline` |
| G5 | **自签名证书** | 内网 90% 是自签证书，不处理就 100% 弹警告 | 连自签证书主机：① 默认（跳过校验）② 关闭「跳过远程计算机身份验证」 | ① 直接连上 ② 能弹出并识别证书警告，选择后可继续；两种情况下凭据仍加密传输 |
| G6 | **多显示器** | 运维桌面普遍双屏 | 双屏（同 DPI）设为 `multimon` 全屏连一次；再切回窗口模式 | 多屏铺满、无黑边错位；切回窗口模式后尺寸正确；`resolution` 面板显示与实际一致 |
| G7 | **DPI 缩放** | 125%/150% 笔记本 + 外接屏是常态 | 系统缩放分别设 100%/150%/200%，重启应用，检查主窗卡片、抽屉表单、会话全屏 | 无错位/截断/文字溢出；卡片操作区不压地址行；缩放切换后窗口仍可拖拽到第二屏 |
| G8 | **精简镜像** | 部分客户环境删了远程桌面组件 | 在移除 `mstsc.exe` / `mstscax.dll` 的镜像上启动应用，切三种执行器各连一次 | 失败时给出"组件不可用"的明确提示（不是白屏/静默失败）；FreeRDP 可用时应能连上；设置页「关于」能看出哪个组件缺失 |

## 3. 与自动化的关系

| 项 | 能自动化的部分 | 不能自动化的部分 |
|---|---|---|
| G1 | `.rdp` 字段生成（`verify:capabilities`）、认证失败事件码 | 真实 NLA 握手、服务端策略差异 |
| G2 | 凭据存储/解密、日志脱敏 | 域账号真实登录 |
| G3 | 网关字段映射与三种 usagemethod 的取值 | 真网关 + 网关凭据交互 |
| G4 | 探测三态口径 | 真实网络拓扑 |
| G5 | `authentication level` 取值 | 证书弹窗与用户选择 |
| G6/G7 | 主窗布局矩阵（`verify:layout`）、无障碍（`verify:a11y`） | 会话窗口在真实多屏/混合 DPI 下的表现 |
| G8 | 组件缺失判定与回退路由（`verify:capabilities`） | 真实精简镜像上的启动 |

## 4. 发版前的固定顺序

```bash
npm ci
npm run typecheck
npm run verify                 # 含 verify:cli / verify:docs
npm run build:win              # 产物在 release/，末尾生成 SHA256SUMS.txt
# 再按 §1 的 G1–G8 在真机上跑一遍，结果填进 §2
```

顺序不要交换：**先全绿再上真机**，真机时间只用来验证环境相关的东西，不用来发现语法错误。
